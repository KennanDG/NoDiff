# NoDiff Windows and Microsoft Store publishing

NoDiff ships the Electron UI and a local FastAPI runtime as one Windows desktop application.

## Build a local Windows installer

From `frontend` on Windows:

```powershell
npm ci
npm run desktop:build:windows
```

The build performs these steps automatically:

1. Uses `uv` + PyInstaller to freeze `backend/src/agent_runtime/api/main.py` into `backend/dist/nodiff-agent-runtime/`.
2. Type-checks and builds the Vite/Electron application.
3. Copies the frozen sidecar into Electron `resources/backend/nodiff-agent-runtime/`.
4. Produces an x64 NSIS installer under `frontend/release/`.

The installed Electron process starts FastAPI before creating the application window, waits for `/health`, and sends a graceful shutdown command to FastAPI before Electron exits.

## Reserve NoDiff in Microsoft Partner Center

Use the MSIX product path for the Microsoft Store build.

1. Open Partner Center -> Apps & games.
2. Select **New product**.
3. Select **MSIX or PWA app**.
4. Enter `NoDiff` and select **Check availability**.
5. If available, select **Reserve product name**.

Microsoft currently holds an unused reservation for up to three months, so create a submission before the reservation expires.

After the product exists, open **Product management -> Product identity** and copy these values exactly:

- `Package/Identity/Name`
- `Package/Identity/Publisher`
- `Package/Properties/PublisherDisplayName`

## Build the Store MSIX

Set the Partner Center identity values in the same PowerShell session that runs the build:

```powershell
$env:MICROSOFT_STORE_IDENTITY_NAME = "<Package/Identity/Name>"
$env:MICROSOFT_STORE_PUBLISHER = "<Package/Identity/Publisher>"
$env:MICROSOFT_STORE_PUBLISHER_DISPLAY_NAME = "<Package/Properties/PublisherDisplayName>"
$env:MICROSOFT_STORE_DISPLAY_NAME = "NoDiff"
$env:MICROSOFT_STORE_VERSION = "1.0.0"

npm run desktop:build:store
```

The Store artifact is written to `frontend/release-store/`.

`MICROSOFT_STORE_VERSION` defaults to `1.0.0`. Keep the major version at `1` or higher and increase the version for future Store releases. The Store reserves the fourth Windows package version component for its own use.

Do not hard-code the Partner Center identity values until the app name has been reserved. The values generated by Partner Center are authoritative and must be copied exactly.

## Store listing checklist

After reserving the product, use **Product release -> Start submission** and complete:

- Pricing and availability
- Properties and category
- Age ratings
- Packages: upload the generated `.msix`
- Store listing: description, screenshots, Store artwork, support/privacy information
- Submission options and certification notes

At least one screenshot is required; four or more real in-app screenshots are recommended. Capture the coding task/diff review, source-control workflow, agent settings/provider selection, and skills/agent workflow.

The repository contains package artwork in `frontend/build/` and `frontend/build/appx/`. A larger Store artwork pack is maintained separately from the executable build assets.

## Signing model

Use MSIX for the Microsoft Store submission. Microsoft re-signs MSIX/AppX packages after certification, so a CA-trusted signing certificate is not required for the Store upload itself.

The NSIS `.exe` build is useful for direct/manual installation and testing. If NoDiff is distributed directly outside the Store, sign that installer separately with an Authenticode certificate to avoid Windows reputation and trust warnings.

## Pre-submission checks

Before uploading the Store package:

1. Install and launch a release build on a clean Windows user profile.
2. Confirm the FastAPI process appears only while NoDiff is running and disappears after NoDiff closes.
3. Verify local runtime data is created under `%APPDATA%\\NoDiff\\agent-runtime`.
4. Test provider configuration, GitHub flows, repository selection, and one full coding-agent run.
5. Run the Windows App Certification Kit against the final Store package.
6. Publish a privacy policy URL before certification. NoDiff can transmit prompts, repository content, and other user-provided data to configured model/API providers, so the Store listing should clearly disclose that behavior.
